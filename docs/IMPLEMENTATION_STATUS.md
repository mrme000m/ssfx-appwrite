#### Execution Flow — OAuth

```
User clicks "Connect cTrader"
  → sites/ssfx-hq/js/api.js::AuthAPI.startOAuth()
    → GET https://auth.mrme.tech/auth/ctrader/start
      → functions/auth-oauth/src/main.js::handleStart()
        → getServiceConfig() reads ctrader_oauth from service_config
        → signState() generates HMAC-signed state token
        → createRow() in ephemeral_tokens table (10-min TTL)
        → 302 redirect to cTrader consent screen

User approves → cTrader redirects to /callback?code=...&state=...
  → functions/auth-oauth/src/main.js::handleCallback()
    → verifyState() validates HMAC + TTL + single-use
    → exchangeCtraderCode() → cTrader token endpoint
    → Appwrite Users.create() → new Appwrite user
    → slave_accounts.upsert() with encrypted tokens
    → Appwrite Account.createSession()
    → Set a_session_<PROJECT_ID> cookie
    → 302 redirect to app.mrme.tech/#/onboarding
```

#### Execution Flow — PIN Login

```
User enters username + PIN
  → POST https://pin.mrme.tech/pin-login
    → functions/auth-pin/src/main.js::handlePinLogin()
      → Query slave_accounts by username
      → verifyPin() using scrypt salt:hash
      → Appwrite Account.createSession()
      → Set cookie → return { authenticated: true, role: ... }
```

#### Execution Flow — Token Refresh (Python → Function)

```
Python service needs access_token
  → POST https://api-internal.mrme.tech/internal/ctrader/refresh
    → Header: x-internal-key matches INTERNAL_API_KEY
    → functions/api-internal/src/main.js::handleRefresh()
      → acquireGrantLock() on grant_locks table row
      → decrypt() refresh_token from slave_accounts
      → refreshCtraderToken() → cTrader OAuth endpoint
      → encrypt() new tokens
      → updateRow() slave_accounts with new tokens + expiry
      → releaseGrantLock()
      → return { access_token, expires_in }
```

### 3.3 Over-Abstraction

| # | Finding | Location | Explanation |
|---|---|---|---|
| 1 | **`AppwriteClient` singleton in `ssfx_server/`** | `ssfx_server/appwrite_client.py` | Wraps the already-simple `create_appwrite_client()` from `shared/` with a singleton pattern + config caching. Only used by `ssfx_server/`. The `shared/` factory is sufficient; the singleton adds testability problems and hidden global state. |
| 2 | **`_UpdateBuffer` in `executor.py`** | `ssfx_trader/executor.py` | Complex internal class for aggregating rapid signal updates. Has its own async task lifecycle, buffer dict, and flush logic. Could be simplified to a simpler `deque`-based batcher or removed if signal rate is low enough. |
| 3 | **4 separate agent classes with similar structure** | `agent_harness/agents/*.py` | Each agent repeats the same `__init__`, `provider.chat_completion()`, parsing, and error-handling pattern. A small base class or factory would reduce duplication. |
| 4 | **Dual auth paths in `ctrader_client/`** | `ctrader_client/broker_auth.py` + `ctrader_client/appwrite_auth.py` | Two separate auth modules for broker-backed vs Appwrite-native mode. Could be unified behind a single `AuthProvider` interface. |
| 5 | **Signal store backend abstraction** | `ssfx_trader/stores/base.py`, `sqlite_signal_store.py`, `appwrite_signal_store.py`, `noop_store.py` | The abstraction is reasonable, but the default "noop" fallback when Appwrite fails means **trading runs without signal history** silently. This is a dangerous default. |
| 6 | **`DataServiceClient` in both `agent_harness` and `ssfx_trader`** | `agent_harness/tools/data_service.py` + `ssfx_trader/market_context.py` | Two separate HTTP clients for the same data service API. Could share a single client in `shared/` or `ctrader_client/`. |

## 8. Security Posture Check

| # | Control | Status | Evidence |
|---|---|---|---|
| 1 | No plaintext token logging | 🟢 | `auth-oauth` callback redacts tokens; `api-internal` never logs decrypted tokens |
| 2 | Row-level permissions on user tables | 🟢 | `slave_accounts`, `trade_configs` have RLS per AGENTS.md §Critical Rules |
| 3 | Encrypted tokens at rest | 🟢 | AES-GCM-256 in `slave_accounts` tokens column |
| 4 | HMAC-signed OAuth state | 🟢 | `signState()` / `verifyState()` in `_shared/index.js` |
| 5 | PIN hashing | 🟢 | scrypt with random salt in `auth-pin` |
| 6 | Internal API key gate | 🟢 | `x-internal-key` header checked in `api-internal` |
| 7 | Admin API key gate | 🟢 | `x-admin-key` checked in `ssfx_server/admin_api.py` |
| 8 | Telegram webhook verification | 🟢 | `X-Telegram-Bot-Api-Secret-Token` checked |
| 9 | Grant-level distributed locks | 🟢 | `grant_locks` table prevents thundering-herd refresh |
| 10 | Session validation via HTTP | 🟢 | Cookie checked against Appwrite `/account` endpoint |
| 11 | No function `.env` files with secrets | 🟢 | `.env` files are `.env.example` templates only |
| 12 | Cloudflare Tunnel ingress | 🟢 | No direct VM public IP exposure |
| 13 | Per-account risk kill-switches | 🟢 | `max_open_risk_pct`, `max_positions`, `trading_enabled` in schema |
